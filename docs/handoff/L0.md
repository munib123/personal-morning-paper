## Known issues

- The migration was checked statically: `tests/l0/migration.test.ts`, plus a statement-by-statement comparison with §7. It has not been run against a local Postgres, because the Docker daemon was not running. Its first real run is the push.
- Expect two Supabase advisor warnings, both harmless here:
  - **Extension in public:** §7 creates `vector` without a schema.
  - **Mutable function search_path** on `increment_llm_usage`: the function is security invoker, so this allows no privilege escalation.
- `articles.content_text` can be read with the publishable key, because §7 gives `read_all` on `articles` and the migration grants select on it. It is never displayed, but the Data API exposes it. Column-level grants would close this gap, but they would break `select('*')` on `articles` for every non-admin client.
- **Source homepages** on feed or CDN hosts point at the publisher's site. For example, `feeds.bbci.co.uk` → `https://www.bbc.com`, and `hacker-news.firebaseio.com` → `https://news.ycombinator.com`. The reason: L3 shows the homepage host as `ArticleCard.sourceDomain`.
- **Overlapping sources:** the 114 RSS rows include the hnrss.org front page and five DEV tag feeds, which overlap the `hacker-news` and `dev-to` API rows. `url_hash` dedupes articles with the same URL.
