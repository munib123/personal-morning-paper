## Done

Everything below runs on real data in the shared Supabase DB.

- **`runIngest()`** (`src/server/ingest/index.ts`, §9.3 contract, signature unchanged). It covers all 117 seeded sources: 114 RSS feeds plus the `hacker-news`, `dev-to` and `arxiv` API rows. The pipeline:
  1. Fetch each source in a pool of 8 (15 s timeout, SubahBot UA, conditional GET with ETag / Last-Modified).
  2. Decode the charset: BOM, header charset, XML prolog (ISO-8859-1 → windows-1252), invalid UTF-8 fallback, leading whitespace (Dezeen).
  3. Parse with rss-parser and apply the 48 h window and the 60-per-source cap.
  4. Canonicalize the URL (utm_* / fbclid / fragment / trailing slash stripped, params sorted) and hash it (`url_hash = sha256`).
  5. Dedupe in memory (the better copy wins), then against the DB.
  6. Page phase, for new items only: og:image / twitter:image, and Readability when the feed text is under 80 words. It runs 5 at a time, with at most 400 fetches and a 150 s budget.
  7. Bulk insert in chunks of 200 with `ON CONFLICT (url_hash) DO NOTHING`, `status='raw'`, `lang='en'`.
  - `runIngest` writes no `job_runs` rows.
- **Adapters:**
  - Hacker News: top stories with score ≥ 50, read from the first 90 ids. Text is "title. og:description".
  - Dev.to: top=1 for javascript, webdev, ai, devops and python, one request at a time, with `cover_image ?? social_image`.
  - arXiv API: newest 10 each of cs.AI, cs.LG, cs.CL and cs.SE, 3.1 s apart, with one retry on 503 "Rate exceeded". The window is at least 96 h. One row per paper (versionless `https://arxiv.org/abs/<id>`).
- **Source health on every run:**
  - `last_fetched_at` and `last_status` (FeedCache JSON: httpStatus, etag, lastModified, error, items, at).
  - `fail_count` is reset by a success. A source goes `active=false` on its 5th failure in a row.
  - Bot walls (403, an empty 202, an HTML body) are recorded and never bypassed.
- **`GET|POST /api/cron/ingest`** (`src/app/api/cron/ingest/route.ts`):
  - Needs `Authorization: Bearer ${CRON_SECRET}`, compared with `timingSafeEqual`. An unset secret is always 401.
  - Runs `runIngest({})` only and writes one `job_runs` row `job='ingest-cron'`.
  - Returns 200 with `IngestStats` JSON, or 500 `{ error }` after the row is closed as `error`.
  - `runtime='nodejs'`, `maxDuration=300`.
- **`.github/workflows/ingest.yml`**:
  - Runs every 30 min (`*/30`) and on `workflow_dispatch`, with `concurrency: ingest`.
  - Node 24, `npm ci`, a gte-small model cache, then `npm run job:ingest`.
  - `secrets.SUPABASE_URL` → `NEXT_PUBLIC_SUPABASE_URL`.
- **`src/server/ingest/run-cli.ts`** takes these flags:
  - `--only=a,b`, `--max=N`, `--since=H`
  - `--sources` (counts by kind)
  - `--backfill-images` (og:image for up to 300 imageless rows from the last 48 h)
  - `--report` (coverage plus the latest `ingest` / `ingest-cron` job_runs rows)
- **Final-review fixes** (each one was a test that failed first):
  - Row text is cleaned of NUL bytes and lone surrogates before insert. Postgres rejects them, and one bad row used to fail its whole 200-row chunk.
  - The page phase gets `min(150 s, 240 s − elapsed)`, so slow feeds cannot push `/api/cron/ingest` past its 300 s limit.
  - `runIngest` measures time from `min(demo clock, real now)` (§9.7), so a demo clock set ahead never dates rows in the future.
- **Stretch, feed retry:** each feed is retried once, 2 s after a network error (TLS reset or connect timeout, the Al Jazeera case). An HTTP answer such as a 403 is never retried.
- **Tests:** `src/server/ingest` plus the route: 18 files and 126 tests. Every model and network call is mocked: fixtures are served through `vi.stubGlobal('fetch')`, and the Supabase client is a chainable fake.

## Notes for L2

- Rows arrive with `status='raw'`.
- `content_text` is plain text of at most 1,500 words, used only as summarizer input. `word_count` is the count before truncation.
- `lede` is the feed description as plain text, cut to 120 words + "…" when the feed puts the whole article there. When the feed has none, it falls back to the page's og:description.
- HN rows carry `title. og:description` as their text when the page has one. Readability text wins when it is longer.
- arXiv rows have no image: arXiv's og:image is the logo, which is blocklisted, and the page phase skips arxiv.org entirely. Their text is the abstract.
- Dev.to rows have cover images.

## Notes for L0 / integrator

- `runIngest` writes no `job_runs`. L1 writes only `job='ingest-cron'` (from the cron route); `scripts/job-ingest.ts` writes `job='ingest'`.
- `ensureApiSources` is only a safety net for the L0-seeded `hacker-news`, `dev-to` and `arxiv` rows. It never had to insert one: all three kinds were present on every run.
- **Windows exit-code bug:** `process.exit()` while undici sockets are still closing trips a libuv assertion (`UV_HANDLE_CLOSING`), and the process exits 127. `run-cli.ts` avoids it by setting `process.exitCode` instead. `scripts/job-ingest.ts` (L0) still calls `process.exit()`; its run here exited 0, but it may hit the same bug on Windows.
- The one Turbopack build warning ("dynamic filesystem access") comes from `src/server/pdf/styles.ts` (L6), not from L1.
- L2's note about `the-news-international-sports` (its feed carries world news) concerns `seed/feeds.json` (L0). L1 ingests whatever the feed URL serves.
